1. Production support and troubleshooting — highest priority
    1. ⭐ A production application suddenly becomes unavailable. How would you investigate and restore service?
    2. ⭐ A deployment succeeds, but users start receiving errors. How do you troubleshoot, and when would you roll back?
    3. ⭐ Describe a production incident you handled: impact, investigation, resolution, and prevention.
    4. An application becomes slow without any recent deployment. What would you check?
    5. How do you distinguish an application issue from a database, network, or infrastructure issue?
    6. What is the difference between incident resolution, a workaround, and root-cause analysis?
    7. How do you prioritize multiple incidents and decide when to escalate?
    8. What would you include in an RCA document?
    9. How would you investigate an intermittent issue that you cannot reproduce?
    10. How do you communicate status to developers, business stakeholders, and onshore teams during an outage?

    23. A pipeline worked yesterday and fails today without code changes. How would you investigate?

5. Python, Linux, networking, and monitoring
    34. ⭐ Write a Python script that checks multiple application health endpoints and reports failures, with timeouts and exception handling.
    35. ⭐ A Linux server has high CPU, high memory usage, or a full disk. How would you investigate each?
    36. Write a Python script to parse application logs and count errors by type or time interval.
    37. How would you implement retries in an automation script? Which failures should you avoid retrying?
    38. How do you investigate DNS resolution failures, connection timeouts, connection refusals, and TLS certificate errors?
    39. What do HTTP 401, 403, 404, 500, 502, 503, and 504 suggest during troubleshooting?

Prepare four concrete stories: a production incident, an automation improvement, a deployment or Kubernetes change, and a client demo. For each, explain the problem, your actions, the result, and what you improved afterward.
For troubleshooting questions, practice answering in this order: impact → recent changes → evidence → isolate the cause → restore service → verify recovery → prevent recurrence.

Also revise these small gaps:Linux permissions and processes, Kubernetes RBAC, application monitoring with Prometheus/Grafana, and SLA/SLO/SLI plus incident severity.

For a DevSecOps interview, know these core areas:
- SAST — scans source code for security issues without running it. Tools: SonarQube, Checkmarx.
- DAST — tests a running application for vulnerabilities. Tools: OWASP ZAP, Burp Suite.
- SCA — scans third-party/open-source dependencies and licenses. Tools: Snyk, Mend.
- Container scanning — scans container images/OS packages for CVEs. Tools: Trivy, Prisma Cloud.
- IaC scanning — scans Terraform/Kubernetes manifests for misconfigurations. Tools: Checkov, tfsec.
- Secret scanning — detects passwords, tokens, API keys committed to code. Tools: Gitleaks, GitHub secret scanning.
